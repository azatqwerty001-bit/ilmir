# Админка: как это работает

## Самый простой способ — прямо в браузере

Откройте `admin/` на опубликованном сайте. Если Python-сервер не запущен, автоматически работает учебный браузерный редактор без пароля и установки. Измените цену → «Сохранить черновик» → «Предпросмотр». Черновик хранится в localStorage только этого браузера и этого адреса сайта. В обычном меню посетители видят опубликованную версию. Очистка данных браузера удалит черновик; для копии нажмите «Скачать сайт ZIP». В ZIP также обновлён HTML для просмотра без JavaScript.

Это не защищённая онлайн-админка и не сохранение на общем сервере. Она подходит для обучения и подготовки изменений, но не публикует их в GitHub автоматически. Любой посетитель может редактировать свой личный черновик, не меняя сайт для остальных. Серверный режим с паролем описан ниже.


Это рабочая учебная админка с отдельным сервером, а не пароль внутри JavaScript и не сохранение только в браузере. Python 3.9+ запускает API и сайт. Сервер хранит меню на диске; после входа администратор редактирует его через форму. Посетители этого сервера видят сохранённые изменения. GitHub Pages не выполняет Python: для него есть экспорт готового сайта.

## Первый запуск на компьютере

Скачайте репозиторий целиком (GitHub → Code → Download ZIP), распакуйте и откройте терминал в папке проекта. Нужен установленный Python 3.9 или новее.

```sh
python3 admin_server.py --init
python3 admin_server.py
```

В Windows вместо `python3` может использоваться `py`. Первая команда попросит придумать пароль длиной не меньше 12 символов; при вводе символы не отображаются. Пароль не отправляйте в чат. Вторая запустит сайт и напечатает локальный адрес. Откройте `/admin/` по этому адресу и войдите. Этот адрес работает только на вашем компьютере, это не публичная ссылка.

Зависимости устанавливать не нужно. Для Python 3.9+ нужна системная база часовых поясов (на Windows при её отсутствии установите `tzdata`).

## Что попробовать

1. Измените цену капучино → «Сохранить на сервере» → «Посмотреть сайт». Новая цена появится и в полном меню, и на главной. Обновите ранее открытую вкладку.
2. Снимите «Показывать на сайте» — позиция исчезнет для посетителей.
3. Добавьте позицию, выберите «Сезонное» и «Лето», заполните состав, аллергены, порцию и цену, выберите фото-пример, включите показ.
4. Выберите сезон «Лето», измените заголовок и описание баннера, сохраните. Теперь показываются летние позиции. Если в выбранном сезоне нет позиций, баннер скрывается.
5. Для автоматического режима выберите «Автоматически по месяцу». Май–сентябрь — лето, октябрь–апрель — осень/зима, часовой пояс — Москва. Названия, цены, баннер и рецептуры администратор готовит сам; система не придумывает новые напитки. Пока баннер общий для обоих сезонов, используйте нейтральный текст при автоматическом режиме.
6. Перезапустите сервер: меню сохранится. «Выйти» завершает сессию; Escape закрывает демонстрационные диалоги на странице контактов.

Выбор фото ограничен подготовленной галереей проекта. Загрузка новых файлов пока не реализована. ID уникален и состоит из латинских букв, цифр и дефисов. На главной показываются первые три видимые несезонные позиции. Фильтр «Сезонное» показывает позиции только активного сезона.

## Как обновить публичный GitHub Pages

1. Сохраните изменения на учебном сервере.
2. Нажмите «Скачать сайт ZIP». В нём публичные HTML/CSS/JS, изображения и `menu-data.json`; пароля, серверных настроек и сессий нет.
3. Распакуйте ZIP. Загрузите содержимое в корень ветки `main` репозитория через GitHub или Git, заменив соответствующие файлы. Папку `assets` нужно сохранить.
4. Дождитесь успешной публикации GitHub Pages и обновите публичную страницу.

Само сохранение в админке **не изменяет GitHub Pages**. Сервер хранит отдельно рабочее меню, а GitHub — опубликованные файлы. При экспорте обновляется также HTML-резерв для браузеров без JavaScript. Для автоматического сезона браузер выбирает позиции при открытии; без JavaScript используется сезон на дату экспорта. Открытие файлов двойным щелчком может блокировать загрузку JSON: используйте сервер или GitHub Pages.

## Где находятся данные

- `menu-data.json` — исходное меню и данные публичного сайта.
- `menu-render.js` — показ данных на главной и в меню.
- `admin/` — интерфейс редактирования; пароль не содержится в этих файлах.
- `admin_server.py` — сервер, вход, валидация и экспорт.
- `../.ilmir-admin/auth.json` — соль и хеш пароля, вне корня сайта.
- `../.ilmir-admin/menu.json` — сохранённое рабочее меню.

Резервируйте рабочий `menu.json`. Для смены пароля остановите сервер и снова выполните `--init`; сохранённое меню останется. Переменная `CAFE_ADMIN_STATE` позволяет выбрать другое приватное место хранения. При одновременном редактировании двумя людьми сохраняется последний присланный вариант — совместное редактирование пока не поддерживается.

## Что потребуется настоящему заказчику

Этот сервер слушает только `127.0.0.1` и предназначен для обучения. Сессия хранится в HttpOnly/SameSite cookie на 8 часов, пароль проверяется через scrypt, записи требуют входа и проверки Origin, число попыток входа ограничено. Сервер не выдаёт исходники Python, приватные данные и содержимое `.git`.

Для онлайн-админки заказчика понадобятся хостинг Python с HTTPS, Secure-cookie и настроенным доменом, резервные копии, журнал изменений, учётные записи и роли, восстановление доступа и согласованная схема публикации. Альтернатива — готовая CMS с авторизацией. Не выставляйте учебный сервер наружу простым изменением адреса прослушивания. Публичная страница `admin/` на GitHub Pages только объясняет, как запустить сервер, и не даёт права редактирования.

## Проверка разработчиком

```sh
python3 -m unittest discover -s tests -v
```

Тесты используют временное хранилище и случайный тестовый пароль, проверяют вход, Origin, сохранение, валидацию, приватные файлы и отсутствие секретов в экспорте. Рабочее меню и пароль не затрагиваются.
