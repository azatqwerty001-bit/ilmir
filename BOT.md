# Telegram-бот «Тёплый угол»

## Быстрый запуск на Windows

1. Скачайте последнюю версию проекта из GitHub и распакуйте архив. Токен из BotFather не отправляйте в чат.
2. Дважды нажмите `start-bot-windows.bat`. Python 3.10+ уже должен быть установлен, как для нашего сайта.
3. Дождитесь подготовки. При первом запуске появится окно: вставьте токен целиком и нажмите «Сохранить и запустить бота». Кнопка «Показать токен» помогает проверить ввод — не делайте скриншот с открытым ключом.
4. В терминале появится имя `@вашего_бота`. Найдите его в Telegram и нажмите «Запустить» либо отправьте `/start`.
5. Нажимайте «Меню», «Сезонное», «Контакты» или «Помощь».

Не закрывайте окно запуска: бот работает, пока эта программа запущена и компьютер подключён к интернету. Для остановки — Ctrl+C. Для следующего запуска используйте тот же файл: токен повторно вводить не нужно. Если понадобилось заменить токен, остановите бота и запустите `reset-bot-token-windows.bat`. При утечке токена сначала отзовите его в BotFather.

На macOS/Linux — `python3 start_bot.py`. В окружении без графического интерфейса ввод токена скрыт в терминале. При запуске серверного процесса можно использовать уже настроенную переменную `TELEGRAM_BOT_TOKEN`, не записывая ключ в проект. Не вставляйте токен в команду, историю терминала, GitHub или HTML.

## Что умеет

- `/start` — приветствие и клавиатура.
- `/menu` — видимые позиции с ценами, порциями, составом и аллергенами.
- `/seasonal` — только предложения активного сезона.
- `/contacts` — учебный адрес и часы работы.
- `/help` — команды и подсказка.

Тексты передаются обычным текстом, без выполнения HTML из названий блюд. Длинное меню разделяется на сообщения. Бот отвечает только в личной переписке, сообщения групп пропускает. Поддерживает учебные заказы без оплаты. Рассылки, доставку и сбор телефонов не реализует.

## Общая админка с сайтом

Бот читает базу Django при каждом запросе. Запустите также `start-windows.bat`, войдите в админку, поменяйте цену и сохраните. Затем снова нажмите «Меню» в Telegram: появится новая цена. Старые сообщения Telegram автоматически не редактируются. Веб-сервер необязательно держать включённым после редактирования: боту достаточно базы на диске.

Обе программы по умолчанию используют соседнюю приватную папку `.ilmir-production`. Если вы распаковали новую копию проекта в другую родительскую папку, там может создаться другая база. Сохраняйте расположение проекта или задайте одинаковый `CAFE_DATA_DIR` обеим программам. Токен и база не входят в Git и ZIP проекта.

Сезонность та же, что на сайте: вручную либо автоматически по Москве (май–сентябрь — лето, октябрь–апрель — осень/зима). Будущие сезонные позиции и баннер готовит администратор. Контакты пока вымышлены, как на сайте; они заданы в ответе `/contacts`, а не редактируются через панель меню.

## Как устроено

`start_bot.py` подготавливает окружение, миграции и исходное меню. Повторный импорт не перезаписывает изменения. Команда Django `runbot` запускает длинный опрос Telegram (`getUpdates`) через HTTPS с обычной проверкой сертификата. Для получения сообщений не нужны домен и входящие порты.

Токен хранится в `.ilmir-production/telegram-token.txt` вне сайта. На Linux устанавливаются права 0600; в Windows папка наследует права пользователя, поэтому не делайте её общей. Файл токена нельзя пересылать. В журнале не печатаются токен и сообщения посетителей. Последний обработанный номер обновления хранится отдельно и помогает не отвечать повторно после обычного перезапуска. При аварии между отправкой и записью номера возможен повтор последнего ответа — гарантия exactly-once не предоставляется.

Запускайте только одну копию бота с данным токеном. При конфликте (`409`) бот объясняет, что нужно остановить второй процесс. Существующий webhook программа не удаляет автоматически: это мог быть другой работающий бот. Для учебного проекта используйте отдельного бота BotFather. При временном сбое связи выполняется повторное подключение; при отозванном токене запуск останавливается с понятным сообщением.

## Стоимость и ограничения

На своём компьютере обучение не требует хостинга. Для круглосуточной работы позже понадобится постоянно включённый сервер с постоянным диском и доступом к `api.telegram.org`. GitHub Pages бота не запускает. Telegram-токен не является ключом OpenAI; платные API ИИ в проекте не используются.

## Проверки

Тесты входят в `server/cafe/test_bot.py`: команды, изменение цены через базу, скрытые позиции, ручной и автоматический сезон, приватные чаты, деление сообщений, сохранение номера обновления, защита существующего webhook и отсутствие токена в текстах ошибок. Они используют подмену Telegram API и ничего никому не отправляют. Реальный вход к вашему боту будет проверен только на вашем компьютере с вашим токеном.

## Если запуск остановился

Версии начиная с `telegram-bot-v2` различают отказ токена (401/404), отсутствие соединения, DNS, таймаут, ошибку сертификата и ответы сетевого посредника. Сообщения не содержат токен. При завершении больше нет лишнего traceback запускающего скрипта. Надпись «Нажмите любую клавишу» удерживает окно для чтения ошибки: до скриншота её нажимать не нужно. По одной общей ошибке старой версии нельзя определить, верен ли токен.

### Проверка HTTPS на Windows

Начиная с `telegram-bot-v3`, запросы Telegram используют `truststore` и системное хранилище сертификатов Windows (также поддерживаются macOS и Linux). Проверка сертификата и имени сервера остаётся включённой. Это помогает, когда сертификат доверен Windows, но не найден обычным Python-контекстом. Если ошибка остаётся, проверьте автоматические дату/время Windows, обновления системы и настройки сетевого посредника/HTTPS-фильтрации. Не используйте `CERT_NONE` и не отключайте антивирус. При наличии числового кода проверки он показывается без токена и адреса запроса.


## Корзина и учебные заказы (v4)

### Обновление без потери данных

Остановите прежний бот через Ctrl+C и закройте прежнее окно сайта. Распакуйте архив v4 рядом с прежней папкой на Рабочем столе (не внутрь старой папки). Запустите из новой папки `start-bot-windows.bat`, затем `start-windows.bat`. Обе программы сохраняют привычное расположение базы `.ilmir-production` рядом с папкой проекта; миграции автоматически добавляют таблицы и права существующему аккаунту заказчика. Меню, фото и токен не сбрасываются. Если вы изменяли `CAFE_DATA_DIR`, используйте прежнее значение. Для страховки можно заранее скопировать приватную папку данных после остановки программ; не загружайте её в GitHub.

### Как оформить заказ

1. Отправьте `/start`, чтобы обновить клавиатуру. Нажмите «Сделать заказ» или `/order`.
2. Нажатие названия добавляет одну штуку. В корзине доступны «+», «−» и удаление позиции. Каталог разбит на страницы. Лимиты — 10 шт. одного вида и 50 шт. всего.
3. Откройте «Корзина» или `/cart`, проверьте сумму и нажмите «Оформить самовывоз».
4. Выберите «Как можно скорее» либо время через 30/60 минут. Время — московское, оно указано на экране подтверждения. Режим учебный: часы работы не ограничивают оформление.
5. Проверьте позиции, сумму и время. Нажмите «Подтвердить учебный заказ». До этого момента заказа в админке нет.
6. Бот выдаст номер. `/orders` или «Мои заказы» показывает пять последних заказов только текущего гостя.

`/cancel` отменяет **оформление**, сохраняя корзину. Уже отправленный заказ может отменить сотрудник в админке. «Очистить корзину» удаляет все позиции, но не отменяет созданные заказы.

### Действия сотрудника

В Django-админке появился раздел «Заказы». Обновите страницу, чтобы увидеть новые заказы. Откройте заказ, выберите статус и сохраните:

**Новый → Принят → Готов → Выдан**.

До выдачи можно выбрать «Отменён». Назад и через несколько этапов переходить нельзя. Состав, сумма и время заказа доступны только для чтения: это снимок на момент подтверждения. Изменение цены в меню не изменяет уже созданный заказ. Аккаунт заказчика получает права смотреть заказы и менять их статусы, но не создавать их вручную, не удалять и не управлять пользователями.

При каждом изменении статуса создаётся запись уведомления. Запущенный бот отправляет её гостю обычно в пределах одного цикла опроса (около 10 секунд; при очереди и сетевых сбоях дольше). Обновлять старое Telegram-сообщение не требуется: приходит новое. История доставки видна внутри заказа. Если бот остановлен, уведомления остаются в базе и обрабатываются после запуска. При временной ошибке есть повтор, при блокировке гостем ошибка фиксируется без бесконечных попыток.

### Что защищено

- Повтор одного Telegram-обновления не увеличивает корзину второй раз.
- Повтор подтверждения не создаёт второй заказ.
- Перед подтверждением проверяются актуальная доступность, сезон, количество и цены. При изменении цены нужно проверить сумму заново.
- Подтверждение действует 15 минут и привязано к гостю; чужую корзину или заказ подтвердить нельзя.
- Снимок заказа и очередь уведомлений хранятся в базе; перезапуск не очищает их.
- Идентификатор бота основан на его Telegram ID: замена токена того же бота не теряет доступ к его заказам.
- Сетевые ошибки с неопределённым результатом могут привести к повтору Telegram-ответа; гарантия однократной доставки сообщений не обещается. Номер заказа остаётся один.

Хранятся Telegram chat ID, корзина, состав/сумма/время заказов, статусы и записи доставки. Имена, телефоны и адреса гостей не запрашиваются. База приватная. Для реального бизнеса позже понадобятся политика хранения данных, обработка обращений, реальное расписание, защита от спама и хостинг. Сейчас все заказы учебные: настоящий кофе не готовится, деньги не списываются.
